### 1.1. Структура исходного файла и загрузчик

Исходный файл `data/raw/SMSSpamCollection` содержит по одной записи на
строку. Строка состоит из двух полей, разделённых символом табуляции:

```
<label>\t<text>
```

`label` принимает значения `ham` или `spam`, `text` — исходный текст SMS
(включая кавычки, знаки препинания, сокращения и неразрывные пробелы).

Загрузчик `load_sms_dataset()` в `ml/data/load_sms.py`:

1. Строит пути относительно корня проекта через
   `Path(__file__).resolve().parents[2]`, поэтому не зависит от текущей
   рабочей директории и абсолютных путей.
2. Открывает файл с `encoding="utf-8", errors="strict"` — некорректная
   кодировка приводит к явной ошибке `SmsDatasetError`, а не к тихой замене
   символов.
3. Читает файл **построчно** и делит строку через `split("\t", 1)`.
   Благодаря этому кавычки внутри SMS не воспринимаются как начало
   CSV-поля и не склеивают соседние строки. При стандартном
   `pandas.read_csv` с включённым quoting часть сообщений с кавычками
   разбирается неверно, и в результате нередко получают 5 572 строки
   (4 825 ham и 747 spam) вместо 5 574. Наш загрузчик сохраняет **все
   5 574 строки** (4 827 ham и 747 spam); эквивалентный безопасный вариант
   чтения — `pd.read_csv(..., sep="\t", header=None, quoting=csv.QUOTE_NONE)`.
4. Приводит метки к числам: `ham → 0`, `spam → 1`.
5. Возвращает `pandas.DataFrame` со столбцами:

| Столбец | Тип | Описание |
|---|---|---|
| `id` | `int64` | Идентификатор от 1 до N (1..5574 для исходного файла). |
| `text` | `object` (str) | Исходный текст сообщения без изменений. |
| `label` | `int64` | `0` — ham (безопасное), `1` — spam (мошенническое). |

Функция `summarize_sms_dataset(df)` печатает и возвращает словарь с числом
строк (`total_rows`), типами столбцов (`dtypes`), распределением классов в
абсолютных числах и процентах (`class_distribution`), а также по пятью
примерами каждого класса (`examples_ham`, `examples_spam`).

Запуск:

```bash
python -m ml.data.load_sms
```

Скрипт загружает набор, сохраняет его в `data/processed/sms_raw.csv`
(UTF-8, `index=False`) и выводит сводку. Для совместимости с другими
модулями доступен алиас `load_sms(...)`.

### 1.3. Известные ограничения

1. **Только английский язык.** В корпусе отсутствуют русские и казахские
   SMS. Поэтому для проверки многоязычности требуется отдельный набор
   `data/raw/custom_ru_kk.csv` (не менее 100 искусственных SMS на русском и
   50 на казахском) и словарь правил социальной инженерии. Для `ru`/`kk`
   ML-оценка английской модели помечается как ненадёжная.
2. **Spam шире, чем финансовое мошенничество.** Метка `spam` включает
   коммерческую рекламу, подписки, лотереи и другие нежелательные
   сообщения, а не только смишинг/фишинг в строгом смысле. Модель будет
   считать «мошенничеством» и легальный, но навязчивый спам.
3. **Особенности текста.** В корпусе встречаются неразрывные и обычные
   кавычки, неформальные сокращения (`u`, `ur`, `2`, `4`, `txt`, `pls`),
   опечатки, эмодзи и обфускация. Это затрудняет токенизацию и требует
   нормализации (`ml/preprocessing.py`, задание 4), а также устойчивых
   символьных N-грамм.
4. **Дубликаты.** В исходном корпусе есть точные дубликаты сообщений. По
   методике ТЗ они удаляются до разделения на выборки (задание 4), иначе
   одно и то же сообщение может попасть одновременно в train и test и
   завысить метрики.

## 2. Признаки текстовой модели

### 2.1. Стратифицированное разбиение 70/15/15

Функция `create_sms_splits(df, output_path=None, random_state=42)`
(`ml/features.py`) делит данные на обучающую, валидационную и тестовую
выборки в пропорции 70% / 15% / 15%:

1. `train_test_split(..., test_size=0.30, stratify=label)` — 70% train и
   30% temp;
2. `train_test_split(temp, test_size=0.50, stratify=label_temp)` — temp
   делится пополам на 15% val и 15% test.

Оба вызова используют `random_state=42`. Стратификация сохраняет
соотношение ham/spam во всех трёх выборках. Индексы сохраняются в
`data/processed/sms_split.json`:

```json
{
  "train_indices": [ ... ],
  "val_indices": [ ... ],
  "test_indices": [ ... ]
}
```

Для исходного набора из 5 574 строк получается 3 901 / 836 / 837 записей
(округление неизбежно: 70% и 15% от 5 574 не являются целыми числами).
Списки содержат `int`; при целочисленном `df.index` сохраняются его
значения, иначе — позиционные индексы. Алиас функции —
`split_sms_dataset`.

### 2.2. TF-IDF: зачем и как

TF-IDF (Term Frequency — Inverse Document Frequency) превращает текст в
разреженный вектор весов слов. Вес растёт с частотой слова в документе и
падает с частотой слова во всём корпусе:

```
tf(t, d)  = 1 + log(count(t, d))          # при sublinear_tf=True
idf(t)    = log((1 + n) / (1 + df(t))) + 1
w(t, d)   = tf(t, d) * idf(t)
```

где `n` — число документов, `df(t)` — число документов, содержащих термин
`t`. Сублинейное масштабирование `sublinear_tf=True` сглаживает влияние
многократных повторов: десять вхождений слова не дают вес в десять раз
больше, чем одно. Это важно для SMS, где мошенники часто повторяют
«FREE», «CALL», «WIN».

Параметры фильтрации:

* `min_df=2` — отбрасываются термы, встретившиеся только в одном
  документе. Они почти всегда являются опечатками, случайными числами или
  шумом и не обобщаются на новые SMS;
* `max_df=0.95` — отбрасываются термы, встречающиеся более чем в 95%
  документов. Такие признаки почти не различают классы, но занимают
  память;
* `ngram_range=(1, 2)` — словарные униграммы и биграммы;
* `sublinear_tf=True` — логарифмическое сглаживание частоты;
* `stop_words="english"` — опционально (`remove_stopwords=True`); по
  умолчанию стоп-слова сохраняются, чтобы не потерять контекст
  отрицаний и служебных конструкций.

Итоговые векторы L2-нормируются, поэтому косинусное сходство документов
не зависит от длины SMS.

### 2.3. Словные N-граммы (1, 2)

Униграммы (`free`, `win`, `prize`, `account`, `blocked`, `urgent`)
показывают наличие отдельных маркеров. Биграммы добавляют контекст:
`free entry`, `claim prize`, `account blocked`, `urgent action`, `call
now`, `verify account`. Одно слово `account` встречается и в безопасной
переписке, а биграмма `account blocked` гораздо сильнее связана со
смишингом. Биграммы также улавливают устойчивые рекламные конструкции
(`txt stop`, `claim your`, `prize reward`), которые разваливаются при
рассмотрении слов по отдельности.

Ограничение словных N-грамм: они чувствительны к опечаткам и намеренной
обфускации. Форма `urgentba`, `fr33`, `b@nk`, `w1n` не совпадёт со
словарными `urgent`, `free`, `bank`, `win`. Поэтому к словным признакам
добавляются символьные.

### 2.4. Символьные N-граммы `char_wb` (3, 5)

`TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5))` разбивает текст
на последовательности из 3–5 символов **внутри границ слов** (пробелы
добавляются как padding). Например, `free` даёт фрагменты ` fre`, `free`,
`ree `, `ree ` и т. п. Такой анализ:

* **устойчив к опечаткам и обфускации**: `fr33`, `freee`, `f.ree`, `b@nk`,
  `w1n`, `v3rify` сохраняют общие символьные фрагменты с нормальными
  словами;
* **ловит leetspeak и замены символов**: цифры и спецсимволы внутри слова
  не разрушают все n-граммы, поэтому модель всё равно видит сходство с
  `free`, `bank`, `win`, `verify`;
* **помогает морфологии**: для русских и казахских слов (агглютинативные и
  флективные языки) символьные n-граммы выделяют корни, суффиксы и
  окончания (`-ами`, `-ды`, `-лар`, `-ған`), даже если полная словоформа
  не встречалась в обучении;
* **устойчив к редким токенам**: даже при `min_df=2` общих символьных
  фрагментов набирается достаточно, чтобы различать классы.

Плата за это — большее число признаков и рост размерности матрицы. На
исходном наборе после разбиения (3 901 обучающая запись) объединение
словных и символьных TF-IDF вместе с ручными признаками даёт около
42 тысяч столбцов. Поэтому матрица хранится разреженной (`scipy.sparse`).

### 2.5. Шесть ручных признаков

TF-IDF плохо видит некоторые структурные сигналы, особенно после
нормализации, когда URL заменён на `<url>`, а сумма — на `<money>`.
`ManualSmsFeatures` вычисляет шесть признаков для каждого текста:

| Признак | Что измеряет | Почему полезен |
|---|---|---|
| `char_length` | длина текста в символах | Мошеннические SMS часто длиннее: в них есть призыв, сумма, ссылка и контакт. |
| `caps_ratio` | доля заглавных букв среди букв | КАПС используется для давления и привлечения внимания. |
| `exclamation_count` | число `!` и `?` | Избыточная пунктуация — маркер срочности и эмоционального давления. |
| `has_url` | есть ли `<url>`, `http://`, `https://`, `www.`, `bit.ly` | Ссылка — ключевой элемент смишинга; после нормализации текст теряет сам URL, но токен `<url>` остаётся. |
| `has_money_or_phone` | есть ли `<money>`, `<phone>`, `$`, `£`, `€`, `₸`, `руб`, `тг` или 7+ цифр подряд | Денежные суммы и телефоны — типовые атрибуты схем «выигрыш», «перевод», «позвоните». |
| `se_groups_count` | число сработавших групп словаря социальной инженерии | Агрегированный сигнал: срочность, деньги, банк, блокировка, приз, запрос кода. |

Группы социальной инженерии берутся из `ml.rules.detect_se_rules`, если
модуль уже создан. Если он недоступен (например, на этапе выполнения
задания 6), используется встроенный fallback-словарь из шести групп:
`urgency`, `money`, `bank`, `account_block`, `prize`, `code_request`.
Словарь покрывает английские, русские и казахские маркеры. Такой fallback
делает модуль независимым от порядка выполнения заданий и не ломает
импорт.

`MinMaxScaler` приводит ручные признаки к диапазону `[0, 1]`. Без
масштабирования `char_length` (десятки–сотни) подавляла бы `caps_ratio`
(0–1) и бинарные флаги. Масштабирование обучается **только на train**:
`MinMaxScaler` находится внутри `Pipeline`, который входит в
`FeatureUnion`, поэтому при `fit` на обучающей выборке он видит только
train, а при `transform` на val/test использует уже сохранённые
минимум/максимум.

### 2.6. Объединение признаков и защита от утечки данных

`build_sms_feature_union(remove_stopwords=False, include_char_ngrams=True)`
возвращает `sklearn.pipeline.FeatureUnion`:

```
FeatureUnion
├── word_tfidf      : TfidfVectorizer(ngram_range=(1, 2), min_df=2,
│                     max_df=0.95, sublinear_tf=True)
├── char_tfidf      : TfidfVectorizer(analyzer="char_wb",
│                     ngram_range=(3, 5), min_df=2, max_df=0.95,
│                     sublinear_tf=True)
└── manual_features : Pipeline
                      ├── ManualSmsFeatures()   # 6 признаков
                      └── MinMaxScaler()
```

`ManualSmsFeatures` не содержит лямбда-функций и других несериализуемых
атрибутов: `fit` возвращает `self`, `transform` — `numpy.ndarray` формы
`(len(X), 6)` и типа `float64`, а `get_feature_names_out` возвращает имена
`char_length`, `caps_ratio`, `exclamation_count`, `has_url`,
`has_money_or_phone`, `se_groups_count`. Поэтому весь `FeatureUnion`
сохраняется вместе с моделью через `joblib` и даёт одинаковые признаки
при обучении и в веб-приложении.

Правила против утечки данных соблюдаются строго:

1. Сначала выполняется разбиение 70/15/15, и только потом строится
   векторизатор.
2. `fit`/`fit_transform` вызываются **только** на `X_train`, `y_train`.
   Для val и test используется `transform` — без повторного `fit`.
3. `get_top_tfidf_features` при обученном `FeatureUnion` только вызывает
   `transform`; если объект ещё не обучен, он делает `fit` исключительно
   на переданных обучающих текстах и никогда не принимает val/test.
4. `TfidfVectorizer`, `MinMaxScaler` и ручные признаки находятся внутри
   `Pipeline`/`FeatureUnion`, поэтому сохраняются и загружаются как единый
   объект: в приложении невозможно случайно применить векторизатор,
   обученный на других данных.
5. Подбор гиперпараметров и порога выполняется на валидации или
   кросс-валидацией на train; тест используется один раз для финальных
   метрик.

Пример использования:

```python
from ml.data.load_sms import load_sms_dataset
from ml.features import (
    build_sms_feature_union,
    create_sms_splits,
    get_top_tfidf_features,
)

df = load_sms_dataset()
splits = create_sms_splits(df)

train_texts = df.loc[splits["train_indices"], "text"]
train_labels = df.loc[splits["train_indices"], "label"]

union = build_sms_feature_union()
X_train = union.fit_transform(train_texts, train_labels)   # fit только на train
X_val = union.transform(df.loc[splits["val_indices"], "text"])
X_test = union.transform(df.loc[splits["test_indices"], "text"])

top = get_top_tfidf_features(union, train_texts, train_labels, top_n=15)
for class_name, features in top.items():
    print(class_name)
    for name, score in features:
        print(f"  {name}: {score:.4f}")
```

`get_top_tfidf_features` возвращает
`{"ham": [(feature_name, mean_score), ...], "spam": [...]}`. Средний вес
считается по строкам соответствующего класса; служебные ручные признаки в
рейтинг TF-IDF не включаются, чтобы места не занимали масштабированные
`char_length` и `has_money_or_phone`. Результат показывает, какие слова и
символьные фрагменты наиболее характерны для безопасных и мошеннических
сообщений, и используется для интерпретации модели в отчёте.
