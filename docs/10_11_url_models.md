## 2. Очистка данных и устранение артефактов разметки (Задание 10, п. 2–5)

Реализовано в модуле `ml/data/load_url.py` (`prepare_url_dataset`):

1. **Приведение меток к стандарту проекта**:
   - Исходная метка `1` (legitimate) переведена в `0` (`SAFE`).
   - Исходная метка `0` (phishing) переведена в `1` (`DANGEROUS`).
2. **Нормализация и дедупликация**:
   - Удалены пустые и некорректные записи (`validate_url` из `ml/url_features.py`).
   - Схема (`http`/`https`) и доменное имя (`netloc`) приведены к нижнему регистру.
   - Удалены полные дубликаты по нормализованному URL (`435` дубликатов в исходном корпусе).
   - Выполнена стратифицированная подвыборка `60 000` записей (`30 000` безопасных + `30 000` фишинговых, `random_state=42`).
3. **Устранение структурных артефактов разметки PhiUSIIL (`_deartifact_safe_urls`)**:
   - У **13 391** безопасных URL (~45%) удалён префикс `www.` из хоста, чтобы безопасные домены второго уровня (`https://kaspi.kz`, `https://egov.kz`) с `num_subdomains = 0` не классифицировались как аномалия.
   - У **5 975** безопасных URL (~20%) схема `https://` заменена на `http://`, чтобы протокол HTTP сам по себе не давал 100%-ного срабатывания без других признаков риска.
   - К **16 403** безопасным URL (~55%) добавлены реалистичные безопасные пути (`/about`, `/contact`, `/news/article-12`, `/catalog/item`, `/ru/help`, `/docs/index.html`, `/profile`, `/faq`, `/shop`, `/services`, `/ru/cards`, `/ru/tracking`, `/wiki/Main_Page`) и доброкачественные параметры запроса (`?lang=ru`, `?page=1`, `?q=python`).
   - Дополнительно включены синтетические примеры на изолированных доменах для закрепления редких структурных признаков из Задания 9 (сокращатели `bit.ly`/`t.co`/`clck.ru`, IPv4-адреса, Punycode `xn--`, бренд-спуфинг казахстанских и международных сервисов).

## 4. Сравнение алгоритмов классификации URL (Задание 11, п. 1–3)

В модуле `ml/train_url.py` на обучающей выборке (`train`) обучены три модели с подбором гиперпараметров через `GridSearchCV` (`StratifiedKFold(n_splits=3, shuffle=True, random_state=42)`, метрика `f1`):

1. **`LogisticRegression`** (в `Pipeline` со `StandardScaler`, лучшие параметры: `C=10.0`, `class_weight='balanced'`).
2. **`RandomForestClassifier`** (лучшие параметры: `n_estimators=250`, `max_depth=20`, `min_samples_leaf=2`, `class_weight='balanced'`).
3. **`HistGradientBoostingClassifier`** (лучшие параметры: `max_iter=250`, `max_depth=10`, `learning_rate=0.05`).

**Обоснование выбора `HistGradientBoostingClassifier`**:
- Показывает наивысшие значения по всем ключевым метрикам качества на валидации: **Recall = 0.9500**, **Precision = 0.9361**, **F1 = 0.9430**, **F2 = 0.9472**, **ROC-AUC = 0.9807**, **PR-AUC = 0.9797**.
- Нелинейные деревья градиентного бустинга эффективно улавливают взаимодействия признаков (например, наличие пути безопасно при `is_https=1` и отсутствии подозрительных слов, но опасно при сочетании с `num_suspicious_words > 0`, `is_suspicious_tld = 1` или `brand_similarity = 1`).
- Скорость предсказания одного URL составляет ~24 мс (в 4,4 раза быстрее `RandomForest`), что с запасом укладывается в нефункциональное требование НФТ-1.1 (≤ 2 с на запрос).

## 6. Подбор порогов для трёх категорий и оценка на тестовой выборке (Задание 11, п. 5–6)

На валидационной выборке подобраны два порога вероятности `P_url`:
- **`t1 = 0.35`** — граница перехода `SAFE` → `SUSPICIOUS` (обеспечивает полноту обнаружения угроз `Recall = 0.9570` при `Precision = 0.9268`).
- **`t2 = 0.51`** — граница перехода `SUSPICIOUS` → `DANGEROUS` (максимизирует `F2 = 0.9471` при высокой точности `Precision = 0.9368` и `Recall = 0.9497`).

Правило категоризации ссылки:
- `P_url < 0.35` → **`SAFE`** (безопасная ссылка);
- `0.35 <= P_url < 0.51` → **`SUSPICIOUS`** (подозрительная ссылка, требуется осторожность);
- `P_url >= 0.51` → **`DANGEROUS`** (потенциально опасная / фишинговая ссылка).

### Метрики итоговой модели на валидационной и тестовой выборках (при пороге `t2 = 0.51`)

|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| **Валидация (`val`)** | 0.9499 | 0.9368 | 0.9497 | 0.9432 | 0.9471 | 0.9807 | 0.9797 | 4341 | 228 | 179 | 3382 |
| **Тест (`test`)** | **0.9466** | **0.9479** | **0.9363** | **0.9421** | **0.9386** | **0.9788** | **0.9804** | 4491 | 209 | 259 | 3805 |

Все целевые показатели качества из Раздела 3.4 ТЗ (`Recall >= 0.85`, `Precision >= 0.85`, `ROC-AUC >= 0.90`) выполнены с большим запасом. После однократной оценки на тесте модель переобучена на объединённой выборке `train + val` и сохранена в `ml/artifacts/url_model.joblib` и `ml/artifacts/url_model_meta.json`.
